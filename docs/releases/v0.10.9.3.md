# S' MacRDP v0.10.9.3

## Virtual Display and 4K

- **Display → Virtual display** now offers **3840 × 2160 (4K)**. Enable **Keep the selected resolution** to hold the selected size when the client connects or resizes its window. With the toggle off, macrdp follows the client's requested dimensions when supported.
- Virtual-display sizing is independent of physical-screen capture and stays selected when you change video profiles. At Retina (2×), a 3840 × 2160 frame gives a 1920 × 1080-point workspace. The resolution picker controls pixel dimensions. Frame rate and codec come from the video settings and client negotiation.
- The toggle writes `VD_FIXED_SIZE`. Existing virtual-display configurations can still read the legacy `--no-client-resolution` flag when the new setting is absent.

## Local screen recovery

- **Blank — move apps to remote** replaces the old **Detach** option. It uses black cover windows and moves app windows onto the virtual display while a client is connected. On the last disconnect, macrdp removes the covers, restores the display arrangement, and moves windows back to the local display.
- The physical display stays registered with macOS. This removes the old display-disable operation that could leave the built-in display missing even after disconnect or a server restart. The cover process ends on disconnect, and pending resize work cannot raise its covers again after teardown.
- Existing `PRIMARY_MODE=detach` and `--detach-primary` configurations select the new behavior automatically. The former `DETACH_RESTART_ON_STUCK` workaround is no longer used.
- The Controller warns that **Blank — keep apps on Mac (can't lock)** uses exclusive capture, which can prevent Mission Control and Space shortcuts. Use **Keep local screen on** when those shortcuts are needed. With **Displays have separate Spaces** enabled in macOS, create a second Space on the virtual display before using **Ctrl + ←/→** there.

## Keyboard shortcuts and screenshots

- **Ctrl + arrow** points the System Events action at the virtual display when the pointer is outside it. macrdp starts the helper on Control press and reuses it for subsequent shortcuts. If the helper exits, the next key press can start a replacement. Debug logs report helper reuse, queue time and System Events execution time.
- **Cmd + Shift + 3** captures the virtual display. **Cmd + Shift + 4** starts area selection from that display. Add **Ctrl** to either shortcut to copy the image to the clipboard. **Cmd + Shift + 5** opens the Screenshot controls from the virtual display.
- Spotlight looks for the menu-bar item on the virtual display first. **Cmd + Space** continues to switch input sources if macOS assigns that shortcut to input-source switching.

## H.264 playback

- AVC420 packages video data into the graphics stream with one fewer full-payload copy. The resulting bytes match the previous framing.
- With **TCP video pacing** enabled, AVC420 holds the latest capture when a local graphics write stalls and retries when the writer catches up.
- **Responsive capture** can retry an unsent picture when an encoder queue slot opens. In a short 4K Ethernet trial, Main queued 54.7 FPS with this change, compared with 48.8 FPS before it.
- **H.264 Main Profile (Preview)** is available in **Video → Advanced Video**. Main used less video bandwidth and improved decoded luma fidelity in synthetic comparisons. A short 4K Windows RDP trial over Wi-Fi also measured lower ACK queue delay at similar queued frame rates. Built-in presets continue to use Baseline. Check client compatibility before using Main regularly.

## Audio and Controller

- The PCM send queue expires stale packets during a stalled write. When the transport catches up, the queue resumes with newer audio.
- **Audio → Prefer Core Audio Tap** exposes the server’s capture preference. Personal presets remember it, and macrdp can fall back to ScreenCaptureKit.
- **Performance → Audio diagnostics** shows capture sample age, time to hand PCM packets to the transport, and discarded packets. **Advanced → Diagnostics** lets you set the local statistics port.

## Validation recorded

- **PCM audio:** a Windows recording of five flash-and-beep pulses in a 4K H.264 session measured audio within 14 ms of the picture in that trial.

- **Windows App:** with **Keep local screen on**, **Ctrl + ↑** opened Mission Control on the virtual display. After adding Desktop 2 there, **Ctrl + ←/→** switched Spaces.
- **Windows App:** one end-to-end cycle of **Blank — move apps to remote** passed. The server log confirmed that it removed the covers, restored the layout and moved a window back to the built-in display. Windows App reconnected, and macOS still reported the built-in and virtual displays as active.
- **Automated checks:** a protocol-level test negotiated a fixed 3840 × 2160 desktop when a client requested 2560 × 1440. The preview also passed 27 Rust configuration tests, 4 shield protocol tests and 68 Controller tests.
- Validation to date covers the recorded display setup. Blanking recovery during a client resize, screenshot and Spotlight behavior across multiple displays, and shortcut latency across macOS versions still need broader testing.

## Upgrade

Update both **macrdp.app** and **macrdp Controller.app** together. After moving or replacing the apps, use **Status → Repair Installation** if the Controller still points to a previous location. If macOS prompts for permissions, grant Screen & System Audio Recording and Accessibility to the installed server app, then restart it from the Controller.
